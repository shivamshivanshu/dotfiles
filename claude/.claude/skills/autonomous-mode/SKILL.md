# Autonomous mode

- Trigger: only the user's explicit "autonomous mode" / "kick off autonomous". Auto permission mode and plan approval are not triggers; without it, the [[working-style]] gate's stop-and-ask holds.
- Requires a plan approved per the gate; if none exists yet, finish the gate with the user present first.
- Preparation, right after the trigger and with the user present, in order:
  1. On any branch, use a worktree per [[git]] when unrelated edits or another agent share the tree, or when the main checkout is live (stowed dotfiles: `~` links into it); otherwise, if on the default branch, create a branch and switch to it.
  2. From inside it, launch each build/test/verify command the plan names in the background, pointed at the worktree's files, not installed paths (the installed-paths rule in `~/.claude/agents/verifier.md`); one that cannot be is a question for step 3. Skip any that mutate shared state or reach off the machine, running a read-only probe of the same host or tool instead (`ssh <host> true`, `gh auth status`). Failures are expected; only permission or host-access prompts matter — resolve them now, since a prompt after kickoff blocks until the user answers. Confirm the live `~/.claude/settings.json` carries the `git push` `permissions.ask` rules; say so if not.
  3. Ask every remaining question while those run. Kick off once the questions are answered and each command has finished or run ~2 min with no prompt: create the decisions file (below) headed `autonomous: kicked off <ISO>, plan <path>, branch <branch>, worktree <path|none>`, say `kicked off`, and from then on ask nothing. Before the first edit, wait for the commands to finish and log each result in the decisions file as the `<base>` baseline.
- Every material decision — behaviour, scope, safety, or a plan decision; not naming or routine implementation — takes the recommended default and gets one row in `$HOME/claude_notes/scratchpad/<YYYYMMDD>/<topic>-decisions.md` (kickoff day, the plan's `<topic>`): `| # | step | decision | options | taken | why |`. Overflow goes in a `### <#>` section below the table, so the user can point at row N. A material choice with no safe default is a `BLOCKED:` row for that item; carry on with the rest.
- A denied tool call is a decision too: log it, never retry it or reach its effect another way, and take an alternative that does not need it — `BLOCKED:` if none. Give every background run a timeout of ~3× its expected time; on expiry kill it and log a row — `BLOCKED:` if the critical path needs it.
- Every spawned-agent brief states that autonomous mode is on and gives the decisions-file path and the never-autonomous list below, which binds the agent too; the agent takes defaults and returns each material choice as a row for the lead to log.
- After compaction, re-read the decisions file's header before acting: the mode is on while it has a `kicked off` line and no `ended` line.
- Never do these autonomously; log a `PENDING:` row, carry on with work that does not depend on it, and ask in the final report:
  - push, deploy, or send anything external (messages, posts, uploads, state-changing remote calls; read-only fetches and searches are fine);
  - delete anything this run did not create that a revert of the branch cannot restore — untracked or ignored files, stashes, other branches or worktrees, paths outside the repo (`git clean`, `git reset --hard` included);
  - change anything outside the run's worktree (the repo, when step 1 made only a branch) — installs, `sudo`, `$HOME` or system config, restowing. Exempt: `$HOME/claude_notes/`, scratch and temp dirs, and the caches and build outputs tools write as a side effect (`~/.cache`, build output bases).
- A user message mid-run is the latest instruction: act on it and stay in autonomous mode unless it says to stop — then append the `ended` line (below) and give the final report. Work it adds outside the approved plan goes through the gate with the user while they are there; the run continues meanwhile.
- Ends when the plan's last step is verified, or when no runnable work remains (only `BLOCKED:`/`PENDING:` rows): commit, append `autonomous: ended <ISO>` to the header, leave the branch or worktree unmerged for review, then give the final report. Later requests go through the gate again.
- Reporting: one line per milestone (`implementer done`, `tests pass`, `2 fixes applied`); the final report ends with the decisions-file path and lists every `PENDING:` and `BLOCKED:` row. A status request gets a few lines; keep the why in the plan and decisions file. This overrides [[working-style]]'s why-first and ~10-call status rules.
