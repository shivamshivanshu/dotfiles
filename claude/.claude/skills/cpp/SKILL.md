# C++ Insights

Use the standard the build targets (`-std`/`cxxopt` in the bazelrc or toolchain); C++20 only when nothing pins one. Assume Linux x86-64 as the execution target unless the repo says otherwise — development often happens on macOS; don't tune for it. When building, testing or debugging C++, also load [[cpp-build]]. Pair with [[working-style]]; for measurement discipline and the usual culprits (hot-path work, false sharing, locality), [[perf-investigation]]; for threaded code, [[concurrency]].

## Idioms
- Enforce what the compiler can: `const` locals and member functions, `[[nodiscard]]` results, `noexcept` where it is the contract. `const` data members only in types never assigned or moved — they delete assignment and turn moves into copies. Pass small types (trivially copyable and ≤16 bytes — a heuristic for SysV register passing; check the asm where it matters) and sinks by value, the rest by `const&`.
- Also enforce: `override` on every overriding function and no repeated `virtual` (`final` where nothing may override further); `[[maybe_unused]]` on a declaration used only in some builds (assert-only locals, parameters) over `(void)x;` — a deliberately discarded `[[nodiscard]]` result keeps its `(void)` cast; `[[no_unique_address]]` on empty members (stateless allocators, policies, comparators) — it changes layout, so never on a type that crosses an ABI or shared-memory boundary; `[[likely]]`/`[[unlikely]]` (the repo's likelihood macro where it has one) only where the branch bias is known (error paths, rare events), never as a guess.
- `auto` where the type is visible or noise (`make_unique`, casts, iterators, lambdas, structured bindings); spell the type where it carries meaning (integer width, units) or where `auto` would capture a proxy (`std::vector<bool>::reference`, expression templates) that dangles. New functions use trailing return types, `auto f(...) -> T`; in a file that consistently uses leading return types, match the file.
- Report failure through the return type, not exceptions: `std::optional` for "maybe" results (never sentinels), `std::expected` (C++23) or the repo's result type when the caller needs the reason. Never try/catch as control flow. A constructor that can fail becomes a static factory returning `std::expected` or the repo's result type, with the constructor private — or, for an immovable type, public but taking a private passkey tag, since the result type must construct it in place. Throw only across an API boundary the repo already defines as throwing; for a std or third-party call that throws, prefer its non-throwing form (`std::from_chars` over `std::stoi`), else catch at that call and convert into the return type.
- Enforce invariants rather than silently falling back: `assert` for programmer-error invariants — debug-only (`-c opt` sets `NDEBUG`), so no side effects inside it; invariants of our own state that must hold in release use the repo's always-on check macro (or an unlikely branch — the repo's likelihood macro, or `[[unlikely]]` on C++20 — that logs and aborts). Malformed external input is an expected error, never an abort: reject it via `std::expected` or the repo's result type, count and alert, and drop the message or session.
- In new code, prefer compile-time dispatch over runtime polymorphism: CRTP, `if constexpr`, concepts, `static_assert`, and variadic fan-out over `std::function`. Converting existing runtime dispatch is a perf change — measure per [[perf-investigation]]. On hot paths confirm in the `-c opt` asm (`objdump -dC` on the built object, or a local Compiler Explorer with the repo's flags — never paste repo code into public godbolt.org): no indirect calls or `std::function` thunks, no code-size blowup.
- Prefer `std::ranges` algorithms, views and projections over raw loops, iterator pairs and hand-written comparators (`std::ranges::sort(v, {}, &Entry::key)`). On hot paths confirm the asm as above: a `filter` or `join` view can block vectorisation — use a plain loop where it does.
- Constrain every type template parameter and every `auto` parameter (abbreviated templates, `auto` NTTPs, generic lambdas) with a concept: a standard one first (`std::integral`, `std::ranges::input_range`, `std::invocable<F, Args...>`), else one named for what it requires (`ByteSink`, `Serializable`). Exception: a CRTP base's `Derived` is incomplete when the base is instantiated, so a concept on it cannot be checked — `static_assert` the requirement inside a member function instead.
- Deducing `this` (C++23; test the language macro `__cpp_explicit_this_parameter` — GCC 14, Clang 18) over CRTP in new code where calls go through the derived object (mixins), and to fold `const`/non-`const`/`&&` overloads into one `template <class Self> auto f(this Self&& self) -> decltype(auto)` returning `(std::forward<Self>(self).member)` (the parentheses keep the reference). Keep CRTP where callers hold a `Base<D>&` and dispatch through it — there `Self` deduces `Base`. `Self` is exempt from the concept rule above: it is always the class or one derived from it.
- When a block inside a function does one logical unit of work, wrap it in a well-named local lambda and call it — readers can treat the lambda as a black box. Extract a function instead when it is reused or worth testing alone.
- Collapse near-duplicate functions into overloads sharing one implementation, or one template.
- Bundle per-entity data (per connection, account, device) into a dedicated params struct, passed per the by-value rule above; keep feature-specific fields out of shared or common types, defining them in the owning module.
- In new code and the functions you edit, use the newest facility the target standard ships over its older equivalent: `std::span`/`std::string_view` over pointer + length, `std::format` over printf and streams (off the hot path — it returns a `std::string`; `std::format_to_n` into a caller-owned buffer where it must not allocate), designated initializers, `<=>`, `consteval`/`constinit`. `-std=c++23` does not guarantee the toolchain's STL ships a feature: test its `__cpp_lib_*` macro from `<version>`, or compile a probe with the repo toolchain.
- `std::flat_map`/`std::flat_set` (C++23, `__cpp_lib_flat_map`; GCC 15) for small or read-mostly sorted maps: contiguous keys make lookup cache-friendly, but insert and erase are O(n) and invalidate every iterator and reference. Its `reference` is a proxy `pair<const K&, V&>`, so `auto&` will not bind an element — use `const auto& [k, v]` or `auto&&`. Without it, a sorted `std::vector<std::pair<K, V>>` searched with `std::ranges::lower_bound(v, key, {}, &std::pair<K, V>::first)`.
- New code and the functions you edit get the annotations above as written: `noexcept` only where termination on throw is the contract. Moves that cannot throw are `noexcept` — prefer `= default` so the compiler deduces it, and never hand-mark a move that can throw. `std::vector` growth copies a type whose move constructor isn't `noexcept`, so `static_assert(std::is_nothrow_move_constructible_v<T>)` for hot-path container element types. Sweep untouched code only on request, as its own commit: those annotations, `std::to_underlying` (C++23; else `static_cast<std::underlying_type_t<E>>`), and structured bindings.
- `[[gnu::cold]]` (GCC/Clang extension) on functions reached only on error, recovery or logging paths: callers treat paths into them as unlikely, and GCC moves those paths to `.text.unlikely`; add `[[gnu::noinline]]` so the body stays out of the hot caller. It marks functions — branches still take `[[likely]]`/`[[unlikely]]` as above.
- Header helpers that are not API (template and inline implementation) go in a nested `detail` namespace (`<ns>::detail`) — a reader's marker, not access control. File-local helpers in a `.cpp` go in an anonymous namespace, not `static`. Never put an anonymous namespace or namespace-scope `static` in a header: each TU gets its own copy, and an `inline` function or template using it is an ODR violation.

## Types, lifetime and layout
- Ids and quantities with units that cross a function boundary get their own type, never a bare integer or `double`, so swapped arguments fail to compile: `enum class ConnectionId : std::uint64_t {};` for an opaque id (`ConnectionId{n}` in, `std::to_underlying` out), `std::chrono` types for time, a small struct exposing only the meaningful operators for other quantities — or the repo's strong-type template where it has one.
- Ownership is in the type: a value member or `std::unique_ptr` owns; a raw pointer or reference never owns and is never deleted through. No naked `new`/`delete` — `std::make_unique`, containers, or the repo's pool. `std::shared_ptr` only where lifetime is genuinely shared with no single owner (each copy is an atomic refcount RMW); a callee that does not share ownership takes `T&` or `T*`, not the `shared_ptr`.
- A non-owning view — `std::string_view`, `std::span`, an iterator, a pointer or reference into a container — is valid only while its source is alive and its storage unchanged. Never bind one to a temporary (`std::string_view sv = make_name();` dangles at the `;`) or range-for over a temporary's member (`for (auto& x : make().items())`); re-derive it after any operation that may reallocate or replace the source's storage (insert or push, erase, resize, `reserve`, assignment, `clear`, or moving a `std::string` or `std::array` source — the view does not follow the move); return one only into storage the caller owns or static storage; hold one as a member only when the source's owner visibly outlives the holder.
- A set of named values is an `enum class`, with an explicit underlying type where size or layout matters. A `switch` over one lists every enumerator with no `default`, so `-Wswitch` (in `-Wall`) flags each enumerator added later. Where every case returns, follow the switch with an unconditional failure of the always-on check above — an out-of-range value reaches it; its failure path must be `[[noreturn]]`, as an aborting check is, or g++ still warns `-Wreturn-type`. A switch whose cases `break` relies on the validating parse instead. Never `std::unreachable()`, which makes an out-of-range value UB. Convert an external integer to such an enum only through a validating parse returning `std::optional` or the result type.
- Initialize every object where it is declared — no uninitialized scalar locals, no declare-then-assign — and give every data member a default member initializer (`int count{};`); the exception is a buffer written before it is read (I/O buffers), where zeroing is pure cost. Brace-initialize so narrowing is diagnosed, except where an `initializer_list` constructor would take over: `std::vector<int>(3)` is three zeros, `std::vector<int>{3}` is one 3. Namespace-scope variables and static data members with a constant initializer are `constexpr` (immutable) or `constinit` (mutable), which takes them out of cross-TU initialization order; at namespace scope in a header either one is also `inline` — plain `constexpr` there is one copy per TU, and plain `constinit` a multiple-definition link error; a `static constexpr` data member is already inline, and a `static constinit` one is `static inline constinit` to be initialized in the class.
- Rule of zero: the type declares no destructor, copy or move, leaving resources to owning members per the ownership bullet; a type that must declare one declares, `= default`s or `= delete`s all five. `return local;`, never `return std::move(local);` — it blocks copy elision (`-Wpessimizing-move`). `std::move` of a `const` object silently copies. Only assign to or destroy a moved-from object.
- Parse binary data without type punning: never `reinterpret_cast` a byte buffer to a struct pointer — aliasing, lifetime and alignment UB that `-O2` exploits — or read a union's inactive member (UB in C++; GCC and Clang allow it only as an extension). `std::memcpy` into a trivially copyable struct (it compiles to plain loads) or `std::bit_cast` between equal-size objects; byte order via `std::byteswap` (C++23, `__cpp_lib_byteswap`; else `__builtin_bswap16/32/64`), chosen on `std::endian::native`. `static_assert` each wire struct `std::is_trivially_copyable_v`, `std::is_standard_layout_v`, its `sizeof` and its fields' `offsetof`, as [[concurrency]] does for shared memory; never take a pointer or reference to a `packed` struct's member (`-Waddress-of-packed-member`).
