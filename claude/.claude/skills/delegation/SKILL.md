# Delegation

How to delegate work and supervise the agents doing it. Pair with [[working-style]].

- Three kinds of worker, kept distinct because they differ in lifetime and cost: a **subagent** is an unnamed Agent spawn — one-shot, reports back, resumable by its agent ID via SendMessage; a **teammate** is any *named* Agent spawn (agent teams are on in settings) — a persistent in-process member that can self-claim from a shared task list ([[agent-team]]), resumable via SendMessage while alive; each idle wakes the lead, so stop it with TaskStop once its work is done; a **Workflow agent** is one step in a deterministic script. A **fan-in agent** is whichever of these merges the others' output. Name the one you mean.
- Keep the main context small, but decide per task whether delegation earns its cost: it buys context preservation and parallelism at the price of spawn latency, briefing effort, and coordination. Delegate when that price pays off — broad searches, bulk file reading, builds/tests whose output needs filtering (otherwise background the run itself, per Verify), audits, research, and sizeable multi-step or separable work go to subagents or background workflows, which return conclusions, not raw output. Count main-context growth as a cost of inline work: a step whose raw output the main thread need not keep — bulk reads, long logs, build/test output, full diffs, broad searches — goes to an agent that returns the conclusion, even when inline would be quicker. Inline: focused edits, quick lookups, tightly-coupled changes, files already in context. The main thread is the engineering lead: it takes the user's instruction, plans, chooses the execution shape, and holds synthesis, decisions, focused shared-context edits, and just enough inline scouting to write good briefs. Agents do the work.
- For large, parallelisable work, orchestrate multi-agent Workflows (Workflow tool; the keyword `ultracode` opts a turn in) by intent: [[fan-n]] to average out variance on one question, [[stochastic-consensus]] to explore and debate an open problem, [[agent-team]] to execute a separable implementation plan.
- Model: omit the model override on every spawn, so each agent inherits the session model — quality over token cost ([[working-style]] Communicate). Never name a model in a skill or brief. Agent definitions pin no model either, the `codex` bridge included; Codex itself runs the model its profile sets.
  - Wherever a model is named and the surface accepts it (settings, agent frontmatter, `/model`), request the 1M-context variant with the `[1m]` suffix where the model offers one (not Haiku).
- Pick the narrowest agent type that fits, not the catch-all: read-only searching goes to `Explore` rather than a general-purpose agent with full tool access, which takes more turns to reach the same answer. Review and audit never go to `Explore`: it reads excerpts, not whole files.
- Balance model *families*: the `codex` agent bridges to the OpenAI CLI, which reads the repo itself and reports back. Its mistakes don't correlate with a Claude agent's, so pair the two whenever the deliverable is an independent read rather than a diff.
  - Send to codex: diff and code review, audits, bug hunts, "did I miss anything", verifying a claim already made, tracing how something works in unfamiliar code, a second opinion on an approach before committing to it. Keep it read-only and let the main thread own every edit.
  - Keep on Claude agents: focused edits, quick lookups, anything needing this conversation's context or house conventions, and tightly-coupled iteration — codex costs minutes of spawn latency and a fully self-contained brief, which swamps the gain on small work.
  - Brief it as a stranger: absolute paths, the exact question, what "done" means, how to verify. It loads the repo's `CLAUDE.md` but has neither this conversation nor these skills, so inline any constraint that must not be missed. Its sandbox reads only the repo root (`-C`) and system paths (`codex/.codex/claude.config.toml`), so `cat` every input outside the repo root into its brief file — anything under `$HOME/claude_notes/` included, never retyped through the main thread; only its `-o` output file may live outside.
  - It never asks; it ends with `ASSUMPTIONS:` and `NEEDS-CONTEXT:`. Check both before trusting the review, and answer a non-empty `NEEDS-CONTEXT` with a follow-up leg that carries the answers.
  - It spends OpenAI quota, not this session's tokens: background it and keep working.
- For non-trivial changes, code review and simplify passes use the review fan-out in [[fan-n]], with at least one codex leg. Cross-family disagreement is signal — chase it rather than averaging it away.
- Before parallelising implementation, build a dependency tree of the changes and delegate by it — mechanics in [[agent-team]]. Trivial, tightly-scoped, or tangled work stays sequential in one context; the tree is for work that is both sizeable and cleanly separable.
- Always review an agent's code before accepting it: read the diff, check it against the plan and these skills, and correct or re-delegate rather than trust it blind. In a [[doc-reviewer]] run its conformance agent reads the diff; the main thread reads its verdict and `git diff --stat`.
- Spawn Agent calls at most 3 per message: ~16 in one message failed with `Lock file is already being held`, while batches of 2–3 worked. Send the next batch once the previous batch's spawn calls have returned, and re-spawn any that hit the lock error in it.
- Supervise every spawned agent — they can die silently or stall without reporting. At spawn, guess a cutoff from the task's size (a rough guess, not an estimate worth spending time on) and arm a background `sleep <cutoff>` as the wake-up; one timer per batch, stopped once the batch reports. At the cutoff, check each agent — its output file or its own slice of the tree changed since the last check: progressing → re-arm; stalled → kill. Ceiling 3× the cutoff: kill regardless. After any kill, sweep the repo for half-done changes (`git status`/`git diff`) and clean or finish them; run `git worktree list`, `git worktree remove --force` any detached worktree the dead agent created (a `verifier` base re-run), then `git worktree prune`; then hand the dead agent's output file to a fresh agent with a sharper brief to continue from — or finish directly if small.
- Give every subagent, teammate and codex leg an output file: pass its absolute path under `$HOME/claude_notes/scratchpad/<YYYYMMDD>/` (never the harness session scratchpad) in the brief, have it append each finding or completed step as it goes (an implementer logs steps beside its diff), written for the LLM that reads it next — fan-in or replacement: exact paths, symbols and commands, current state and next step, no narrative — and keep everything outside the file to a one-line reply — path plus count or status. The file is the cutoff's progress signal and what a replacement continues from, so a kill loses no work. Codex writes its `-o` file only at the end, so a dead codex leg is rerun, not continued. Workflow agents are exempt: their output never reaches the main context, and a resumed run reuses finished calls. So are read-only agents (`Explore`, `Plan`): their reply is the output.
- Subagents follow these same skills: name the relevant ones in the brief — as `SKILL.md` paths for agents without the Skill tool — have them run task-level ones (e.g. `simplify`) on their slice, and report results back for the main thread to consolidate. The plan gate binds the main thread; a delegated agent executes its brief and reports ambiguity back. In autonomous mode, every brief also carries what [[autonomous-mode]] requires of it.
- Still make focused, shared-context edits yourself rather than delegating them: files already loaded in the main context stay there even when the edit is mechanical; well-specified mechanical edits to files *not* in context go to `simple-implementer`.
